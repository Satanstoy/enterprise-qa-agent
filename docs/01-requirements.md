# 01 需求与验收

员工输入制度或产品问题，可附对话历史。资料使用带文档 ID、版本日期的合成 FAQ 和制度。Agent 提供检索与原文读取工具，模型根据工具结果选择补充检索、读取、追问或结束。

输出应包含任务状态、适用时的回答、引用文档 ID 和原文片段，以及资料缺口。资料冲突时要读取双方原文并核对废止或优先级。D01 的 30 天与 D02 的 15 天都可能适用时，列出两份依据并请用户确认。

| 验收场景 | 证据 |
| --- | --- |
| 有明确答案 | [试用期](../examples/live/01-clear) |
| 文档冲突 | [报销期限](../examples/live/02-conflict) |
| 资料外问题 | [年假](../examples/live/04-out-of-corpus) |
| 改写后的相似问题 | [差旅报销改写](../examples/live/03-paraphrase) |
| 上下文追问 | [试用期结束后](../examples/live/05-followup) |
| 工具失败 | [检索重试耗尽](../examples/live/06-tool-failure) |
| 替换原文后核对答案和动作 | [试用期变体](../examples/live/08-doc-updated) |

评审时把回答与引用逐条对照，并检查 Trace 是否记录了实际读取和适当的后续动作。错误引用和无依据的肯定回答属于关键缺陷。
