# 00 Grill 问题与回答（企业知识问答）

用法：先看 30 秒介绍，再用问题自测。答案里给了代码和示例位置，现场可以直接打开 Trace 对照。

## 30 秒介绍

这个 Agent 帮员工查制度和产品问题。它先检索，再读原文，回答必须带文档 ID 和原文片段。D01 写报销 30 天、D02 写 15 天，两份都没有适用范围和优先级，Agent 不会替用户选 15 天，而是列出冲突并追问。只有文档明确写了废止关系，比如 D06 废止 D05，它才会采用新版本。资料没覆盖就说明缺口，检索工具失败就不回答。

## 一、需求与边界

### Q1：为什么“版本更新”不能直接当成“优先级”？

D02 的版本日期比 D01 新，但制度里没有写“D02 废止 D01”，也没有写适用总部还是子公司。版本日期只能说明发布时间，不能证明适用范围。直接答 15 天会把一个不确定的业务规则说成确定事实，这是题目明确点名的关键缺陷。

代码里 `session.conflicts` 只在两种情况下消解冲突：同一 `key` 的所有声明值一致，或者某份文档的 `supersedes` 明确指向另一份。版本日期不参与优先级判断。

### Q2：那什么情况下可以直接回答？

只检索到 D01 且没有其他冲突时，可以依据 D01 回答 30 天。`examples/01-clear` 是类似路径：问题只命中 D03，Agent 读原文后回答 14 天。`test_clear_answer_is_grounded_in_d03` 校验引用片段确实出现在 D03 原文里。

### Q3：D05 和 D06 为什么可以解决？

D06 原文写了“原 2024 版同时废止”，数据里 `supersedes: ["D05"]`。Agent 读到这层关系后，把 D05 标为 superseded，采用 D06。输出里 `conflict.resolved=true`，`authoritative_doc_id=D06`。这属于“查证后解决”，不是靠版本号猜。

### Q4：资料库没有答案时怎么处理？

先原查询检索一次，没有命中就扩展同义词再检索一次；两次都没有结果，`finish(insufficient)`，返回缺口，不带引用。`examples/04-out-of-corpus` 问年假，输出 `answer_status=insufficient`，`gaps[0].code=NO_DOC`。

## 二、检索与上下文

### Q5：改写后的相似问题怎么还能检索到？

`domain.py` 里有一个很小的同义词表：出差→差旅、多久/几天→期限、之后→结束。策略第一次用原问题检索，必要时把扩展词拼进查询。`examples/03-paraphrase` 的“出差回来多久内要报销”会命中 D01/D02，最后仍然返回冲突。这里没有 embedding，靠的是关键词、标签和意图词；语料变大后要换混合检索。

### Q6：上下文追问怎么处理？

`contextual_query` 在问题很短或含“那、这个、之后”等指代词时，把上一轮用户问题拼进来，并去掉“多久/怎么/什么”等疑问词，避免旧问题的意图压过当前问题。`examples/05-followup` 的“那之后呢”会结合历史定位到 D04，回答试用期结束后的续费和只读规则。

### Q7：为什么不直接用向量数据库？

当前只有 7 份合成文档，关键词检索的结果可解释，出问题能直接看命中词。向量检索会引入 embedding 模型、索引和阈值，不能自动解决冲突判断。生产环境可以先用 BM25 + 向量召回，再让冲突检测读原文。

### Q8：检索返回多份文档时，怎么选最终回答哪份？

先读命中前 3 份原文，再做冲突检测。没有冲突时，按原始问题的意图词选择文档，比如“之后/结束”选 D04，“发票/提交”选 D06；意图词也没有命中时退回检索排名第一。这个选择逻辑在 `policy._select_doc`，不是让模型自由发挥。

## 三、引用与护栏

### Q9：怎么保证引用真的支持回答？

`finish` 工具做三层校验：引用的文档必须已经 `read_doc`；`quote` 必须是原文的逐字子串；有未解决冲突时禁止 `answered`。任何一条不满足，返回 `INVALID_CITATION`、`DOC_NOT_READ` 或 `UNRESOLVED_CONFLICT`，循环继续。`test_invalid_citation_is_rejected` 和 `test_unresolved_conflict_blocks_answered_status` 覆盖这两条。

### Q10：模型能不能自己编一个文档 ID 或片段？

不能通过 `finish`。文档 ID 必须在 `docs_read` 或 `data/docs.json` 里存在，片段必须逐字匹配原文。模型可以生成候选文本，但最终引用要过工具校验。报告里的 `citations` 直接来自 `finish` 的 payload，不是模型自由文本。

### Q11：如果模型提前结束，说“已找到答案”但没读原文呢？

`finish(answered)` 要求有引用，且引用文档必须已读；没有引用会被 `CITATION_REQUIRED` 拒绝，引用未读文档会被 `DOC_NOT_READ` 拒绝。循环会继续，直到补读或触达步数上限。这个设计和项目 1 的 `finish` 覆盖率校验是同一思路。

### Q12：文档内容会不会变成提示注入？

文档是数据，不是指令。工具只返回原文和结构化字段，系统提示要求“只依据原文”。即使文档里写了“忽略之前的指令”，它也不会被当成系统指令执行；最坏情况是它进入引用候选，仍要过原文匹配。当前 demo 没有做更细的注入检测，这是边界。

## 四、失败与状态

### Q13：检索工具失败怎么处理？

第一次失败后改写查询重试一次；第二次仍失败就 `finish(tool_error)`，不生成答案。`examples/06-tool-failure` 注入两次失败，输出没有 `answer` 和 `citations`，`gaps[0].code=SEARCH_FAILED`。`examples/09-tool-recovery` 只失败一次，重试成功，Trace 同时保留失败和成功两步。

### Q14：读取原文失败怎么办？

每个命中文档最多重试一次。如果某份命中文档读不到，策略直接 `tool_error`，不会只凭摘要回答其他文档。原因是没读到的文档可能正好包含冲突或废止关系，跳过它会产生错误结论。

### Q15：资料不足和工具失败在输出上怎么区分？

`insufficient` 表示检索正常但没有覆盖，`gaps` 里有 `NO_DOC`；`tool_error` 表示工具不可用，`gaps` 里有 `SEARCH_FAILED` 或 `READ_FAILED`。两者都不带引用，也都不生成肯定回答。这个区分让运营知道是“没有资料”还是“系统坏了”。

### Q16：替换文档内容后，答案会变吗？

会。`examples/08-doc-updated` 用一份变体数据，把 D03 的 14 天改成 30 天，同一问题回答 30 天。测试 `test_changing_document_changes_answer` 断言答案里有 30 天、没有 14 天。这说明答案跟着原文走，不是硬编码。

## 五、评估与取舍

### Q17：怎么证明这是 Agent，而不是检索脚本？

Trace 能看到“检索 → 读 D01 → 读 D02 → 检测冲突 → 追问”的动作链，以及每次工具结果。`02-conflict` 如果只做一次检索就直接回答，Trace 里不会出现两份原文和 `needs_clarification`。离线策略是确定性参考实现；`live` 模式用同一套工具和 `finish` 校验走真实模型。

### Q18：这个 demo 最大的技术债是什么？

冲突检测依赖人工维护的 `claims`。真实制度是长文本，需要先做条款抽取，再比较同一字段。另一个缺口是用户确认后没有续跑：当前只追问，用户回答“适用 D01”后需要重新发起一次请求。生产化要加澄清状态和会话恢复。

### Q19：如果两份文档冲突，但用户只想让 Agent 推荐一份，怎么办？

当前边界是不推荐。Agent 会说明冲突并请求确认适用制度；如果用户明确说“按 D02”，下一轮可以把 D02 作为用户指定的适用范围再回答。这个 demo 没有实现确认后的状态机，文档里标成下一步。

### Q20：怎么评估回答质量？

三类指标：引用是否逐字支持答案（工具强制）、动作是否随资料变化（替换文档实验）、冲突是否被识别而不是被压平（D01/D02 用例）。这三类都能从输出和测试直接检查。真实模型还需要人工抽检回答语气和完整性，当前 demo 没有做大规模评测。

```bash
python3 -m pytest -q

python3 - <<'PY'
import json
d = json.load(open('/tmp/grill-conflict/output.json'))

PY
```

现场重点看两份引用、`conflict.resolved=false` 和 `followup_question`。再跑 `07-resolved-conflict` 对比 `resolved=true`。

## 七、不会答时的边界

- 被问向量检索：承认当前是关键词 + 标签，说明扩语料后会换混合检索。
- 被问权限：当前所有合成文档可见，没有接企业权限。
- 被问多轮确认：当前只追问，没有确认后的续跑状态机。
- 被问真实模型：离线 Trace 只证明流程和护栏，live 需要自备 key。
